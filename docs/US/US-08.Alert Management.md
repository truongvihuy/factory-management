# 2. Epic Goal

Provide intelligent real-time alert management for abnormal machine conditions.

The module shall detect abnormal events, create alerts, escalate unresolved alerts, manage acknowledgements, resolve alerts, and notify responsible users according to configurable business rules.

# FT-ALT-01 Detect Alert

## US-ALT-001 Detect Abnormal Condition

### Description

**As the** System

**I want** to evaluate telemetry data against configured thresholds

**So that** abnormal machine conditions can be detected immediately.

### Business Value

- Early fault detection
- Reduce downtime
- Prevent equipment damage

### Priority

Critical

### Story Points

8

### Acceptance Criteria

- Evaluate incoming telemetry.
- Compare against machine-specific thresholds.
- Support multiple sensor values.
- Generate an alert event when conditions are met.

# 5. Business Rules

| Rule ID | Description |
|----------|-------------|
| BR-050 | Alert thresholds are configurable per machine. |
| BR-051 | Severity levels: Info, Warning, Critical. |
| BR-052 | Every alert starts with status = Open. |
| BR-053 | Alerts require acknowledgement. |
| BR-054 | Critical alerts notify all responsible users immediately. |
| BR-055 | Duplicate alerts shall be suppressed while the same condition remains active. |
| BR-056 | Alert lifecycle shall be fully recorded. |
| BR-057 | All alert actions shall generate Audit Logs. |

# 7. Non-functional Considerations

## Performance

- Alert generated within **3 seconds** after telemetry is received.
- Alert search response ≤ **2 seconds**.

---

## Availability

Alert services shall achieve **99.99% availability**.

---

## Scalability

Support:

- Millions of alerts
- Thousands of concurrent active alerts
- Multiple factories

---

## Security

Users can only view alerts belonging to factories they are authorized to access.

---

## Auditability

Audit Logs shall be generated for:

- Create
- Acknowledge
- Escalate
- Resolve
- Reopen
- Threshold Changes

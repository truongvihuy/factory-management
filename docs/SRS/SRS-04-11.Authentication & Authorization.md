# 1. Overview

## 1.1 Purpose

This document defines the functional requirements for the **Authentication & Authorization** module.

The module is responsible for authenticating users, managing local accounts, enforcing role-based access control (RBAC), and securing access to system resources based on Company, Factory, and User Role.

This module is the security foundation for all business modules within the Factory Management System.

---

# 2. Business Scope

The module supports:

- Local User Authentication
- User Account Management
- Password Management
- Role-Based Access Control (RBAC)
- Factory-Level Authorization
- Session Management
- Account Lockout
- Password Policy
- Audit Logging

External Identity Providers (LDAP, Active Directory, OAuth, SSO) are **out of scope** for the current release.

---

# 3. Business Rules

- Authentication uses **local accounts** only.
- Each user belongs to **one Company**.
- A user may have access to **multiple Factories** within the same Company.
- Authorization is enforced at the **Factory level**.
- Users may have different roles in different Factories.
- All business modules must enforce authorization before allowing access.
- Disabled users cannot log in.

---

# 4. User Roles

The system supports the following default roles.

| Role | Description |
|------|-------------|
| System Administrator | Manage the entire platform |
| Factory Manager | Manage assigned factories |
| Production Supervisor | Monitor assigned production lines |
| Maintenance Planner | Plan maintenance |
| Maintenance Engineer | Execute maintenance work |
| Operator | Monitor assigned machines |
| Executive | View dashboards and reports |

Additional custom roles may be introduced in future releases.

# 5. Functional Requirements

---

# FR-AUTH-001 User Login

## Description

Users shall log in using:

- Username
- Password

Authentication shall validate user credentials before granting access.

---

# FR-AUTH-002 User Logout

Users shall be able to log out manually.

The system shall invalidate the current session immediately.

---

# FR-AUTH-003 Change Password

Authenticated users shall change their own password.

The system shall require:

- Current Password
- New Password
- Password Confirmation

---

# FR-AUTH-004 Reset Password

System Administrators shall reset user passwords.

Users shall change the temporary password after the first login.

---

# FR-AUTH-005 User Management

Authorized administrators shall:

- Create User
- Update User
- Disable User
- Activate User

User accounts shall not be physically deleted.

---

# FR-AUTH-006 Assign User to Factory

A user may be assigned to one or more Factories.

Assignment information includes:

- Factory
- Role
- Effective Date

Assignment history shall be retained.

---

# FR-AUTH-007 Remove Factory Assignment

Authorized administrators may revoke a user's access to a Factory.

Historical audit records shall remain available.

---

# FR-AUTH-008 Role Management

The system shall support role assignment.

Each Factory assignment shall have one role.

Examples:

| Factory | Role |
|----------|------|
| Factory A | Operator |
| Factory B | Maintenance Engineer |

---

# FR-AUTH-009 Authorization Enforcement

Every business request shall validate:

- User Identity
- Company
- Factory Authorization
- Role Permission

Unauthorized requests shall be rejected.

---

# FR-AUTH-010 Password Policy

Passwords shall support configurable policies including:

- Minimum Length
- Uppercase Letter
- Lowercase Letter
- Number
- Special Character

Password history may be enforced.

---

# FR-AUTH-011 Account Lockout

The system shall lock an account after a configurable number of failed login attempts.

Only authorized administrators may unlock locked accounts.

---

# FR-AUTH-012 Session Management

The system shall support:

- Login Session
- Session Expiration
- Automatic Logout after inactivity

Session timeout shall be configurable.

---

# FR-AUTH-013 User Profile

Users may update:

- Full Name
- Email
- Phone Number
- Password

Role assignments cannot be modified by users.

---

# FR-AUTH-014 User Search

Support searching by:

- Username
- Full Name
- Company
- Factory
- Role
- Account Status

Support pagination and sorting.

---

# FR-AUTH-015 Factory Access Overview

Authorized administrators shall view:

- Users assigned to each Factory
- Assigned Roles
- Assignment Date
- Account Status

---

# FR-AUTH-016 Permission Verification

The system shall verify permissions before users perform:

- Create
- Update
- Delete (Logical)
- Approve
- Export
- Configure

Permission checks shall occur on every secured operation.

---

# FR-AUTH-017 Audit Logging

The system shall record:

- Login
- Logout
- Failed Login
- Password Change
- Password Reset
- User Created
- User Updated
- User Disabled
- Factory Assignment Changed
- Role Changed
- Account Locked
- Account Unlocked

Each audit record shall include:

- User
- Timestamp
- IP Address (if available)
- Action
- Result

# 7. Non-functional Considerations

## Security

- Passwords shall be securely hashed and salted.
- Sessions shall use secure authentication tokens.
- All authentication endpoints shall use HTTPS.
- Authorization shall be enforced on every protected request.

---

## Performance

- Login requests should complete within **2 seconds**.
- Authorization checks should not noticeably impact application performance.

---

## Availability

- Authentication services should achieve **99.9% availability**.
- Active sessions should survive temporary service interruptions where applicable.

---

## Reliability

- Failed login attempts shall always be recorded.
- Audit logs shall be immutable.
- User permissions shall take effect immediately after assignment changes.

---

## Data Integrity

- User accounts shall never be physically deleted.
- Historical role assignments shall remain traceable.
- Authentication logs shall not be modified.
